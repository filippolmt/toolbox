# Image build gotchas — backstory in [`docs/internals/`](../../docs/internals/)

- **Passwordless sudo**: base apt layer ships `sudo` + `/etc/sudoers.d/toolbox` (`ALL …NOPASSWD: ALL`, UID-agnostic by design) so runtime `sudo apt install …` works; container is `AutoRemove` so it's ephemeral. Caveat: sudo writes into bind mounts (`/workspace`, `~/.toolbox/*`) land `root:root` on host. Smoke test asserts setuid `sudo`. → [sudo](../../docs/internals/image-build.md#passwordless-sudo)
- **Docker CLI checksum**: `fetch-docker` stage has no upstream `.sha256` — pin + HTTPS only (T-01-08). → [docker-checksum](../../docs/internals/image-build.md#docker-cli-checksum)
## Dockerfile build layout

### Fetch stages and the COPY block

static binaries in parallel `fetch-<tool>` stages (`/out` → `COPY --link`), and those COPYs are declared **below the whole RUN tail**, just above `USER toolbox` — `--link` makes each layer independent of the filesystem beneath it, so a bump moves one layer instead of the tail. **Never place a RUN below that block, and never make a tail RUN read a copied file** — either drags the COPY back above the tail and costs every puller the whole tail again (the regression that motivated this moved half the image; figures in ADR 0002).

### The tail is empty, and stays empty

**No npm or pip install in the final stage** — held by `TestFinalStageInstallsNothingFromAPackageRegistry`; `pnpm` is exempt because corepack never writes to a prefix a COPY could carry. The exceptions and the cost of getting it wrong: → [build-layout](../../docs/internals/image-build.md#build-layout-parallel-fetch-stages--an-empty-tail), [Archive Drift](../../CONTEXT.md#archive-drift).

### Version ARG scoping

**Declare every version ARG immediately above the single RUN that consumes it, never as a block at the top of the stage**: an in-scope ARG lands in the cache key of every RUN below it (the `|N` prefix in `docker history`), so one block keyed all 21 tail RUNs on all 14 versions and any single bump rebuilt the whole tail. Held by `TestFinalStageARGsScopedToTheirRUN`. Scoping them made cost positional — `(version RUNs at or below the bumped one) + 1`, measured — which is what made emptying the tail worth doing; the rule outlives the tail it was written for, because it applies to any version ARG that lands back in the final stage.

### Load-bearing orderings and the bound

**No ordering in the final stage is load-bearing any more**, and with the tail empty there is nothing left to order. Two were (`oci` above `graphifyy`, `playwright` above `playwright-cli`), both couplings between tail RUNs sharing one global tree, and both ended when the first of each pair moved into a fetch stage. What keeps the second pair honest is the functional `playwright-cli skill install` check in `smoke-test.sh`, which is what proved the inversion harmless. `MAX_LAYERS` is **6**, and lives in `.github/scripts/invalidation-floor.sh` — one literal, CI reads it. It is now calibrated well above what any bump can cost: a fetch-stage bump moves one layer.

### Moving a tool out of the tail

Sorting cannot make a tool near the top of the tail cheap, so the fix was to move every one of them OUT, and that is done: each lives in its own `fetch-*` stage, where a bump costs one `--link` layer whatever its position. Two shapes, both to copy from when adding a tool:

- **npm** — `FROM node-base`, `npm install -g --prefix /out/usr/local`, verify by running the binary **through `/out`**, `prune-node-weight` the installed tree, `freeze-mtimes` last. Copy `fetch-codex`. A stage that rewrites a binary into a wrapper (`fetch-claude-code`'s `env -u DO_NOT_TRACK` shim) has to strip the `/out` prefix off the resolved target and refuse a target equal to the wrapper's own path — the wrapper names the path the file will have *after* the COPY, so it cannot be run in-stage, and `readlink -f` on a regular file returns that file, which would have it exec itself.
- **pip** — `pip install --break-system-packages --root /out`, which reproduces the system layout (`dist-packages` under the interpreter's own minor) so the final image's own pip still resolves `pip show`; verify with `PYTHONPATH` pointing into `/out`. Copy `fetch-graphify`, and take its base image with it. A venv under `/opt/<tool>` is the alternative when a tool wants isolation (`fetch-oci`). Either way the `__pycache__` purge goes **after the last invocation of the CLI it purges**: every verification run writes bytecode back.

**`node-base` is the only place the node image is named.** Every npm stage and the pip one derive from it, because an npm global tree is only valid on the runtime that resolved it and pip's `dist-packages` path is derived from the interpreter's minor version — both break silently when two stages drift apart. Held by `TestNodeStagesShareOneBaseImage`.

**There are two reasons to move a tool out, and the second is the bigger one.** Cadence is the first: a bump of a tool near the top of the tail rebuilds everything below it. **Archive Drift is the second**: every tail RUN is parent-chained below the unpinned base apt layer, so an archive update moves the whole tail, for nothing anyone edited — ADR 0002 measured 587 MB of 639 on a one-line bump. A tool in a fetch stage moves only when its own `/out` bytes change. Rank candidates by **bytes × drift frequency**, not by total size.

**An apt package a moved tool needs goes in the base apt layer** (`COPY --link` carries files, not dpkg state) — that layer is rebuilt on every drift anyway, so the bytes ride free; what they cost is that they now move *with* it, so this is a trade only for a package a fetch stage genuinely cannot carry.

**A version-derived package set needs a guard before it can be frozen there.** `playwright install-deps chromium` computes its set from the installed playwright version, so a Renovate bump moves it with no edit in the Dockerfile, and a missing lib ships a browser that will not start behind a green build. The frozen list is the **19 packages playwright names, not the 109 apt resolves them to** — pinning transitives breaks on a Debian rename; re-derive with `install-deps --dry-run chromium` on a bare bookworm minus everything that is a dependency of something else in the set (identical on both arches, checked). The guard is `playwright deps` in `smoke-test.sh`, which asks `install-deps --dry-run` against the finished image and fails unless playwright reports the set complete. It lives in the smoke test and not the build because **a tail RUN must never read a copied file** — that is what drags a COPY back above the tail. `docker-ci` runs the smoke test on every `internal/build/assets/**` change, and a playwright bump is one by definition. Mirror this shape for any other dynamic set; never freeze one without it.

### Gate baseline

The gate's baseline is the immutable `sha-<commit>` tag, not `:latest`: `:latest` lags when a publish is cancelled, which bills one commit for another's churn and lets a re-run compare a manifest against itself. See ADR 0002 follow-up 2.

### Reproducible layers

Every fetch stage ends with `freeze-mtimes` (mtime freeze) so layer digests depend on content alone. **A stage that ships a git checkout runs `freeze-git` over each one first**, before that stage's `chmod -R a+rwX`; **the repack flag is `-F`, never `-f`**, and the helper names `--git-dir`/`--work-tree`, never `-C` (which discovers upward, and the OMZ plugins sit inside the OMZ working tree). `TestFreezeGitMakesACheckoutAFunctionOfItsCommit` runs the reassembled helper; `TestGitCheckoutStagesCallFreezeGit` holds the call sites. **No `FROM` is pinned by digest** — `rtk-builder` on arm64 is knowingly non-reproducible for it, accepted at the stage and not excused in the gate. **A build-stage COPY copies `/out/ /`, never a single file to a path**: a `--link` layer materialises its own destination directories, so a synthesised `/usr/local/bin` is stamped with the build clock however frozen the file is, and the layer digest moves on every rebuild — measured on rtk, whose amd64 binary is a checksummed tarball and byte-identical across builds while its layer was not. Set the mode in the stage, not on the COPY. Held by `TestBuildStageCOPYsCopyWholeTree`. `make build` seeds from GHCR `buildcache-main`; `docker-publish-reusable.yml` gates on the moved-layer count. → [Invalidation Floor](../../CONTEXT.md#invalidation-floor), [Fetch Nondeterminism](../../CONTEXT.md#fetch-nondeterminism), [ADR 0002](../../docs/adr/0002-layer-ordering-by-invalidation-floor.md), [build-layout](../../docs/internals/image-build.md#build-layout-parallel-fetch-stages--an-empty-tail)

- **Node package weight prune spares functional `.md`**: `prune-node-weight` (written by `fetch-base` beside `freeze-mtimes`, takes one or more trees) deletes any `.md` — including runtime assets shipped as markdown — so it excludes `skills`/`skill` directories **by name, not path**, for every stage rather than per call site. The playwright-cli skills (`SKILL.md` + `references/` under `playwright-core/lib/tools/skills/<name>/`, plus the `@playwright/cli/skills/` copy) are the live case, and the reason the match is by name: `@playwright/cli` is pinned but pulls `playwright-core` on a floating range, and an upstream relocation of those trees turned an older `-path` exclusion into a no-op. The second half of the guard is per stage and stays there — `fetch-playwright-cli` ends with `test -s …/lib/tools/skills/playwright-cli/SKILL.md`, which is what went red when that happened. Add one for any tool bundling `.md` it actually uses. `TestPruneNodeWeightSparesSkillTrees` runs the reassembled helper. → [node-prune](../../docs/internals/image-build.md#node-package-weight-prune)
- **A vendored runtime is deduplicated by symlink, never by deletion**: `fetch-codegraph`'s platform package vendors its own Node beside the library, and the final stage's base image already ships that major. The stage asserts the two majors match, symlinks the vendored copy at `/usr/local/bin/node` and re-runs `codegraph --version` through it. **The assert is the load-bearing half** — drop it and an upstream bump past the base image's Node degrades silently onto an older runtime instead of failing the build. Same rule for any future bundled runtime; the weight prune still never touches the package holding the binary. Held by `TestVendoredRuntimeAssertsMajorBeforeSymlink`. → [ADR 0016](../../docs/adr/0016-image-size-two-denominators.md)
- **A size claim names its denominator**: pull (compressed blobs) and disk (uncompressed) are different numbers by a wide margin here, and Python trees vs opaque binaries invert the ranking between them. Which one a change improves decides whether it is worth taking. Published-blob encoding is set on the push step's `outputs:` **and on its `cache-to:`** — the two must agree, or `force-compression` re-encodes every restored layer on every publish instead of once. → [Size Denominator](../../CONTEXT.md#size-denominator), [ADR 0016](../../docs/adr/0016-image-size-two-denominators.md)
- **Delete only from the layer that created the bytes**: an overlay `rm`/`strip` against anything a lower layer shipped copies the file up and pays for it twice, so stripping a binary the base image shipped is a net increase, not a saving. Every weight cut belongs in the stage that produced the file. Corollary for the `az` and `oci` layers: **the `__pycache__` purge comes after the last invocation of the CLI it purges**, because each of them runs `az`/`oci` as root to verify the install and every such run writes bytecode back — a purge placed above the checks ships what it just removed. Held by `TestPycachePurgeFollowsTheLastCLIRun`. → [Creating Layer](../../CONTEXT.md#creating-layer), [ADR 0016](../../docs/adr/0016-image-size-two-denominators.md)
- **Two Docker version streams**: `DOCKER_CLI_VERSION` (29.x) and the `go.mod` Moby SDK (`moby/moby/client` v0.x + `moby/moby/api` v1.x — the deprecated `docker/docker +incompatible` module is gone) move independently; the client is built with `client.New(client.FromEnv)`, which negotiates the API version. Don't align numerically. → [docker-streams](../../docs/internals/image-build.md#two-docker-version-streams)
- **`build` declares its Docker surface, and it is two methods** (meaning + rationale: [Declared Docker Surface](../../CONTEXT.md#declared-docker-surface), [ADR 0010](../../docs/adr/0010-each-module-declares-the-docker-methods-it-calls.md)): `localStore` (`ImageInspect`, for `LocalRepoDigest`) and `imageBuilder` (`ImageBuild`, shared by `BuildImage` and `BuildOverlay`), both **unexported** — don't reintroduce `client.APIClient` here, and don't export these to share them. `localimage.overlayBuilder` is the `ImageInspect`+`ImageBuild` pair, and its `buildOverlay` seam var stays a **wrapper, not an assignment**, so a test can name the type it stubs. Tests here drive `dockertest.Fake` (the shared double, governed by [container-runtime.md](container-runtime.md)), which must **never** embed `client.APIClient`. Pinned by `TestLocalRepoDigest`, `TestBuildOverlayComposesFromBaseImageID`, `TestFakeIsNotAnAPIClient`.
- **Tool versions pinned**, Renovate-bumped. No per-tool opt-out — every CLI is installed unconditionally. → [tool-pinning](../../docs/internals/image-build.md#tool-version-pinning)
- **Go version single source = go.mod `toolchain`** (Renovate-bumped). Dockerfile `ARG GO_VERSION` is fallback-only — injected via `--build-arg` everywhere (Makefile `GO_IMAGE`, `mergeBuildArgs` runtime.Version, image workflows). Don't re-pin Go in the Dockerfile or add a Renovate `GO_VERSION`/`GO_IMAGE` manager. `docker-ci` triggers on `go.mod` so a Go bump still smoke-tests the image. `golangci-lint` likewise: one literal `GOLANGCI_VERSION` in the Makefile, CI reads it. → [go-version-sot](../../docs/internals/image-build.md#go-version-single-source-of-truth)
- **rtk arm64 / Rust base traps**: GLIBC mismatch, tag scheme `<ver>-slim-<distro>`, slim ships no curl/ca-certs. → [image-build](../../docs/internals/image-build.md)
- **Homebrew in image**: default prefix `/home/linuxbrew/.linuxbrew` (bottles work only there), world-writable + system `safe.directory` (variable UID), runtime `brew install` ephemeral like apt, analytics/auto-update off. Private GitLab taps via glab credential helper in system gitconfig. → [homebrew](../../docs/internals/image-build.md#homebrew), [gitlab-credential](../../docs/internals/shell-start.md#gitlab-git-credential-helper-glab)
- **System gitconfig is written in two places, on purpose**: the Dockerfile layer carries settings that are properties of the git this image *ships* (Homebrew's `safe.directory`, `http.version`); `entrypoint.sh` carries what only a running container knows (the `safe.directory` wildcard, the bridge credential helper). System scope in both, never `--global` — `~/.gitconfig` is a host mount. **Never remove `http.version = HTTP/1.1`, and never narrow it to a host**: without it most clones and fetches from github fail. **Pinned in two stages, both load-bearing** — dropping the `fetch-base` one breaks the build itself, and only on a cache cold enough to rebuild those stages, which is what kept it latent. Held by `TestGitHTTPVersionPinned`, which brackets per stage so one pin cannot cover for the other. → [system-git-settings](../../docs/internals/image-build.md#system-git-settings)
- **`/usr/local/bin/glab` is a flock shim, not the binary**: real glab lives at `/usr/local/libexec/glab` (`fetch-glab` stage). `~/.config/glab-cli/config.yml` is one host-shared RW mount across every toolbox container, and GitLab's refresh token is single-use — two containers refreshing at once race an unlocked read-modify-write and the loser gets `invalid_grant`, sometimes taking the whole token family down. The shim serializes on `flock $HOME/.config/glab-cli/.toolbox-lock` (`-w 10`, then degrades to unlocked — a human mid-`glab auth login` must not wedge every other container). Two invariants outrank the locking and are held by `internal/build/glab_flock_shim_test.go`, which reassembles the shim from the Dockerfile `printf` block and **runs** it: **never fail closed** (unset `HOME`, read-only or foreign-UID config dir all fall through to an unlocked run — `mkdir -p` returns 0 on an existing unwritable dir, so the probe must be a real write) and **never run twice** (lock held on fd 9 through `exec`; don't reintroduce a `flock -E <code>` sentinel — flock passes the child's status through verbatim, so a colliding glab exit re-runs a mutating command). Guards its own re-entrancy: `init.d/60-glab.sh`'s credential helper resolves back to the shim via `command -v glab`. Don't point the credential helper or any Dockerfile RUN at `/usr/local/libexec/glab` directly — that bypasses the lock. → [glab-flock-shim](../../docs/internals/shell-start.md#gitlab-git-credential-helper-glab)
- **SSH host-key trust**: image bakes `/etc/ssh/ssh_config.d/10-toolbox.conf` (`accept-new` + `known_hosts` on the state mount) so git-over-ssh doesn't re-prompt on the RO `~/.ssh` mount. Don't make the ssh mount writable; don't add `ssh-keyscan` boot seeding. Adding any new top-level embedded asset (like `ssh_config.toolbox`) = 3 synced edits: `//go:embed` directive in `internal/build/embed.go` + Dockerfile `COPY` + the expected-entry list in `TestTarEmbeddedContext`. → [ssh-host-key-trust](../../docs/internals/image-build.md#ssh-host-key-trust)
- **Adding `init.d/<NN>-<tool>.sh` requires 3 synced edits**: (1) write script, (2) `InitScript` field on the matching `internal/catalog/catalog.go` `Entries` row, (3) the `count -ne N` gate **and** its `N (M catalog InitScripts + K system …)` message in `internal/build/assets/smoke-test.sh`. `TestCatalogInitDBijection` (Go) catches (1)+(2); `TestSmokeTestInitDCountLiteral` derives all three numbers in (3) from the catalog + the embedded `init.d/`, so a forgotten bump fails `make go-test` — don't count by hand, let the test name the number.

## Adding shell completion for a CLI requires 2 synced edits

### (1) Generate in the tool's own fetch stage

(1) generate `_<tool>` into `/out/usr/share/zsh/vendor-completions/_<tool>` **inside the tool's own fetch stage, before `freeze-mtimes`** — either by running `<tool> completion zsh` there or by extracting a pre-built `_<tool>` from the release tarball/repo (precedent: bat, fd, eza, brew). Never in a shared final-stage layer: that pins every contributing COPY above it and lowers the Invalidation Floor for all of them (ADR 0002). Only a CLI installed *in* the final stage generates its completion there, and `pnpm` is the last one that is;

### (2) Bump the smoke-test floor

(2) bump the `-ge N` floor in `_zsh_vendor_completions_check` (`internal/build/assets/smoke-test.sh`) — the only literal left, the prose inventory is gone.

### How the number is derived

`TestSmokeTestVendorCompletionsFloor` derives N from the embedded Dockerfile (every literal `vendor-completions/_<tool>` write site) plus `vendorCompletionsUnparseable`, the short declared list for completions no parse can see: kubectx/kubens (written through a `${tool}` loop variable) and bwrap/curl/rg (shipped by their apt packages, no Dockerfile write site). So write the target path literally and the test tells you the number; only a loop-written or apt-shipped completion needs a hand edit, in that list. Keep the parse narrow — a clever regex is the fragile part.

### Build failure vs runtime floor

Both Dockerfile write paths run under `set -eux`, so a broken generator fails the **build** (that is what caught the cf completion regression, not the smoke test); the runtime gate is a floor (`-ge`) whose job is the net-drop alarm — extras pass silently, and it echoes the directory listing so a failure names the files. (Pre-bash-removal there was a third edit in `bashrc.sh`; with bash gone as an interactive shell, the runtime loader is removed and zsh-only vendor completions are pre-baked at build time.)

- **Starship prompt symbols must be width-deterministic**: PUA Nerd Font, ASCII, or unambiguous-narrow only — never EA-Ambiguous chars (`☸`) or emoji+VS16 (`☁️`); the four module symbols in `starship.toml` are pinned to PUA with codepoint comments. Ghostty mode-2027 width ≠ ZLE `wcwidth()` on those classes → ghost chars on Backspace. Don't "restore the prettier default symbols". → [prompt-glyph-width](../../docs/internals/shell-start.md#prompt-glyph-width)
- **`ENV SHELL=/bin/zsh` is load-bearing**: nothing else puts `SHELL` in the container env (zsh keeps it *non-exported*), so tools resolving their shell from `$SHELL` alone (herdr panes, tmux) fall back to dash. Value tracks the passwd shell `entrypoint.sh` writes; smoke test asserts PID 1's environ, never `$SHELL` (bash fabricates it from `/etc/passwd`). → [shell-env](../../docs/internals/shell-start.md#shell-in-the-image-env)
- **UTF-8 locale baked**: `ENV LANG=C.UTF-8` in the final stage — debian-slim defaults to POSIX, under which ZLE renders UTF-8 bytes as `<ffffffff>` (autosuggestion ghost text from history). `LANG` only, never `LC_ALL` (it would outrank the user's `env:` passthrough); no `locales` package needed (`C.utf8` is glibc built-in). Smoke test asserts `locale charmap`. → [utf-8-locale](../../docs/internals/shell-start.md#utf-8-locale)
- **User config sourced from `zshrc.d`**: `zshrc.sh` sources `~/.toolbox-state/zshrc.d/*.zsh` last (after OMZ and the alias block) with **alias expansion off** — zsh expands aliases at parse time, so a snippet defining a function named like a shipped alias (`h`, `g`, `d`, `k`, `l`, `tf`, …) is a parse error that discards the rest of that file. `~/.zshrc` is not an alternative: the Dockerfile truncates it on every rebuild. Smoke test (`_zsh_user_rc_check`) asserts the function survives the alias, and its snippet must define the function *before* unaliasing or the assertion degrades to "file was sourced". → [user-config](../../docs/internals/shell-start.md#user-config-in-zshrcd)
- **rtk hook auto-wiring + privacy lockdown**: `RTK_TELEMETRY_DISABLED=1`, `RTK_TEE=0` load-bearing. → [rtk-hooks](../../docs/internals/privacy.md#rtk-hook-auto-wiring--telemetrytee-lockdown)
- **Never write a glyph as a literal character in an image asset**: a tool that cannot encode the Basic Multilingual Plane PUA empties it in place, leaving valid syntax and no glyph — which has already shipped twice, as every icon in `statusline-command.sh` and as `git_branch` in `starship.toml`. Each file escapes them the way its own format allows and its own hazards require: `statusline-command.sh` uses explicit UTF-8 bytes (`$'\xef\x80\xa1'`), because a bash `\uXXXX` escape is converted through `LC_CTYPE` and renders as text under a C locale, which no `export` inside the script can fix since `LC_ALL` outranks it; `starship.toml` uses TOML `\u` / `\U`, decoded by the parser with no locale involved. Held by the `managed statusline` and `baked starship symbols` blocks of `smoke-test.sh` — one renders the script and re-runs it under `LC_ALL=C`, the other reads the parsed TOML. `bash -n` and a TOML parse both stay green through either failure, and a literal glyph in an assertion is blanked in step with the bug it guards. → [managed-statusline](../../docs/internals/shell-start.md#managed-statusline)
- **DO_NOT_TRACK image-wide, claude exempt via wrapper**: `/usr/local/bin/claude` is a generated `env -u DO_NOT_TRACK` shim, not the npm symlink — the var kills claude's Statsig feature flags (Remote Control, `/doctor` ✗). Don't revert to a symlink; smoke test asserts the shim. → [do-not-track](../../docs/internals/image-build.md#do_not_track--claude-wrapper)
- **Skill discovery paths diverge**: Claude reads `~/.claude/skills/`, every other bundled agent (Codex, pi) reads the cross-agent `~/.agents/skills/` — wrappers shipping a SKILL.md need dual-install, two roots whatever the agent count. Two sites: `init.d/60-glab.sh` (delegates to `glab skills install`) and `init.d/61-herdr.sh` (writes the file itself from `herdr --skill`, one `~/.agents` pass gated on Codex **or** pi). Roots come from `CLAUDE_CONFIG_DIR`/`CODEX_HOME` with the `~` fallback, never a bare `$HOME` path — the Dockerfile sets both and the tools honour them. **`~/.agents` is container-local**, not a bind like `~/.claude`: `mkdir -p` it, never gate on it, or the cross-agent half silently races whichever script happens to create it first (init.d runs backgrounded in parallel). Held by `TestHerdrInitInstallsBothSkillPaths` + `TestHerdrInitWiresPi`. → [skill-paths](../../docs/internals/shell-start.md#skill-discovery-paths-diverge-between-claude-and-the-other-agents)
- **A bundled agent is not a wired agent**: a catalog row plus the Dockerfile install layer put the binary on `PATH`; the `init.d` layer is what makes rtk, atuin and herdr *see* it (`10-rtk.sh`, `65-atuin.sh`, `61-herdr.sh` — one block per agent each). Meaning and why: [Agent Wiring](../../CONTEXT.md#agent-wiring). → [skill-paths](../../docs/internals/shell-start.md#skill-discovery-paths-diverge-between-claude-and-the-other-agents)

Held by `TestHerdrInitLocksClaudeSettings`.
- **Local overlay Dockerfile ≠ image build**: `~/.toolbox/Dockerfile` is a host-side, opt-in overlay (`internal/localimage` + `build.BuildOverlay`), NOT part of this baked image. It's **append-only over the resolved base**: `FROM <base image ID>` is injected, empty context (RUN-only, no COPY/FROM), built into `ghcr.io/filippolmt/toolbox:local` — so entrypoint/init.d/UID mapping are inherited unchanged, no catalog/smoke/Renovate edits. Marker-gated rebuild (base ID + Dockerfile sha256), fail-loud, adopted on the next fresh container. The marker's directory is a **declared input** — `Ensure` takes `plan.StateDir`, never re-derives a state root from the Dockerfile's sibling; the sibling-derived default survives only as the fallback for a session with no state mount, because an absent overlay marker rebuilds on every shell. One marker per state dir is load-bearing, not incidental: `:local` is a single global tag, so sessions sharing a state dir must share the marker or each can read "matches + present" for an image the other overwrote (`TestEnsureKeepsTheMarkerUnderTheGivenStateDir`, `TestEnsureRebuildsForASiblingsOverlay`, `TestEnsureStillGatesRebuildsWithNoStateDir`, `TestFallbackTracksTheDefaultStateMount` — the drift guard on the fallback, since that is the one path the package derives itself). Don't route new baked tools through it — that's the `add-cli` path. → [local-overlay](../../docs/configuration.md#local-overlay-dockerfile)
