# SDD gotchas — backstory in [`docs/sdd.md`](../../docs/sdd.md)

- **SDD `.gitignore` fence**: `toolbox sdd init <key>` writes a fenced block under `# >>> sdd-managed/<key> (toolbox)` from `Skill.GitignoreEntries` globs (patterns, not enumerated paths — survive upstream bumps). Nil entries → fence skipped. Write logic lives in the `internal/configedit` SDD seam (`SetSDDEnabled` yaml flag + `Write`/`RemoveSDDGitignore` fence, `EnableSDD`/`ReconcileSDDGitignore` compose them; `configio.RemoveFence` is the delete counterpart to `SpliceFence`) — both `cmd/sdd.go` (CLI, enable-only) and `configui.SaveSDD` (TUI, enable+disable, Doctor-gated yaml then post-commit fence loop) route through it. Routing is only half the identical-state claim: **both must also resolve the same two paths** — the flag into `configedit.Resolve(WhereLocal, cwd)` (the walked-up project file; a fresh one in a subdir would shadow the repo config wholesale), the fence into `filepath.Join(cwd, ".gitignore")` (the directory the workspace mount writes; `GitignoreEntries` are anchored globs a repo-root fence would not match). The claim is a test, not prose: `TestCLIAndUISDDWritesAreIdentical` drives both real entry points and compares bytes, at the project root and in a subdir. → [sdd-gitignore](../../docs/sdd.md#sdd-gitignore-fence)
- **`sdd` is workspace-only** (meaning + rationale: [Config Scope](../../CONTEXT.md#config-scope), [ADR 0011](../../docs/adr/0011-the-sdd-opt-in-is-anchored-to-the-workspace.md)): `configedit.WorkspaceOnlyKey` is the one authority on which keys the Global layer may not be written — ask it, never restate the set. `configui.openEditor` refuses `enter` on the `sdd` row in `ScopeGlobal` (the row still displays, the `$EDITOR` escape stays open, a hand-written global flag stays legal at load time and still enables the skill everywhere); `resetToDefault` clears the flag in either scope but reconciles the fences **only** in `ScopeRepo`, and **against the post-reload effective set, never `nil`** (reset clears one layer; a flag kept in the other still enables the skill, which still needs its fence) — doing it from Global would strip one workspace's fences for a file that applies to all. The predicate answers *which layer may write the key*, never *which files the key owns*: `reconcileArtefactsAfterReset` dispatches the fence call on the `sdd` key itself, so a second member of the set inherits nothing. Pinned by `TestWorkspaceOnlyKeys`, `TestOpenEditorRefusesWorkspaceOnlyKeyInGlobalScope`, `TestOpenEditorAllowsWorkspaceOnlyKeyInRepoScope`, `TestResetWorkspaceOnlyKeyClearsFencesInRepoScope`, `TestResetWorkspaceOnlyKeyKeepsFencesInGlobalScope`, `TestResetInRepoScopeKeepsFencesAKeptGlobalFlagStillNeeds`.
- **SDD steps override + gsd skill-form**: `sdd.<key>` accepts bool shorthand OR `{steps: [[…]]}` (replaces registry `InstallSteps` wholesale; tokens validated — no whitespace/`;`). gsd claude default is `--claude --global --config-dir ./.claude` (skill-form, hyphen-routable `/gsd-<cmd>`; the old `--claude --local` colon layout broke every gsd suggestion). Sentinel stores `version|steps` so a steps edit re-runs the bootstrap without a version bump. → [sdd-install-steps](../../docs/sdd.md#sdd-install-steps)
