4. Creare `cmd/root.go` con:
   - `var cfgFile string` per flag `--config`
   - `var rootCmd = &cobra.Command{Use: "toolbox", Short: "Gestione del container di sviluppo toolbox", Long: "CLI per avviare, fermare e buildare il container toolbox."}`
   - Funzione `Execute()` che chiama `rootCmd.Execute()` e fa `os.Exit(1)` su errore
   - `init()` con `cobra.OnInitialize(initConfig)` e `rootCmd.PersistentFlags().StringVar(&cfgFile, "config", "", "config file (default: .toolbox.yaml, ~/.toolbox.yaml)")`
   - Funzione `initConfig()` che implementa per D-04 e D-05:
     a. Se `cfgFile != ""` usa `viper.SetConfigFile(cfgFile)`
     b. Altrimenti: chiama `setDefaults()` (definita in config package), poi `viper.SetConfigName(".toolbox")`, `viper.SetConfigType("yaml")`, `viper.AddConfigPath(home)`, `_ = viper.ReadInConfig()` (ignora errore -- D-05 zero-config), poi `viper.AddConfigPath(".")`, `_ = viper.MergeInConfig()` (progetto vince -- D-04)
     c. `viper.SetEnvPrefix("TOOLBOX")`, `viper.AutomaticEnv()`
   - Funzione `setDefaults()` che usa `viper.SetDefault()` per ogni campo individuale (NON nested objects -- per evitare Pitfall 2 di RESEARCH.md):
     - `viper.SetDefault("image.name", "toolbox")`
     - `viper.SetDefault("image.tag", "local")`
     - `viper.SetDefault("build.context", ".")`
     - `viper.SetDefault("build.dockerfile", "docker/Dockerfile")`
     - Per mounts: NON usare SetDefault (array) -- gestire in config.Load() come fallback

   ATTENZIONE: Usare `os.UserHomeDir()` (stdlib Go 1.12+) per risolvere `~`, NON `go-homedir` (dipendenza non necessaria per D-04 discretion).

   - Struct `Config` con campi `Image ImageConfig`, `Mounts []Mount`, `Build BuildConfig` -- tutti con tag `mapstructure`
   - `ImageConfig{Name string, Tag string}` con mapstructure tags
   - `Mount{Source string, Target string, ReadOnly bool}` con mapstructure tags
   - `BuildConfig{Context string, Dockerfile string}` con mapstructure tags
   - Metodo `(c *Config) ImageRef() string` che ritorna `c.Image.Name + ":" + c.Image.Tag`
   - Funzione `DefaultMounts() []Mount` che ritorna i 5 mount di default per D-07:
     ```go
     []Mount{
       {Source: "~/.claude", Target: "/home/toolbox/.claude", ReadOnly: false},
       {Source: "~/.gitconfig", Target: "/home/toolbox/.gitconfig", ReadOnly: true},
       {Source: "~/.gitconfig-dbm", Target: "/home/toolbox/.gitconfig-dbm", ReadOnly: true},
       {Source: "~/.ssh", Target: "/home/toolbox/.ssh", ReadOnly: true},
       {Source: "/var/run/docker.sock", Target: "/var/run/docker.sock", ReadOnly: false},
     }
     ```
     NOTA: `~/.secrets` NON incluso di default per D-08.
   - Funzione `Load() (*Config, error)`:
     a. Crea `cfg := &Config{}`
     b. `viper.Unmarshal(cfg)` per popolare da Viper
     c. Se `cfg.Mounts` e' nil o vuoto, usa `DefaultMounts()`
     d. Ritorna cfg

2. Creare `internal/config/config_test.go`:
   - `TestDefaultMounts`: verifica che DefaultMounts() ritorna 5 mount, che `~/.secrets` NON e' presente, che `~/.claude` e' ReadOnly=false, che `~/.ssh` e' ReadOnly=true
   - `TestImageRef`: verifica che `Config{Image: ImageConfig{Name: "toolbox", Tag: "local"}}.ImageRef()` ritorna `"toolbox:local"`
   - `TestLoadWithoutConfig`: verifica che Load() senza file YAML usa i defaults (image.name="toolbox", mounts ha 5 elementi)

3. Creare `internal/mount/resolve.go`:
   - Funzione `ResolveMounts(mounts []config.Mount) (resolved []string, warnings []string)`:
     a. Per ogni mount: espandi `~` con `os.UserHomeDir()` (sostituisci prefisso `~/` o `~` esatto)
     b. `os.Stat(src)` -- se non esiste: aggiungi a warnings, `continue` (D-09: skip, non bloccare)
     c. Se esiste: formato Docker bind `"source:target:ro"` o `"source:target:rw"` basato su `m.ReadOnly`
     d. Ritorna resolved e warnings
   - Funzione privata `expandHome(path string, home string) string`

4. Creare `internal/mount/resolve_test.go`:
   - `TestExpandHome`: verifica che `~/.claude` diventa `/Users/xxx/.claude`
   - `TestResolveMountsSkipsMissing`: crea mount con path inesistente, verifica che produce warning e non include nel resolved
   - `TestResolveMountsFormat`: crea mount con path esistente (usa `t.TempDir()`), verifica formato `"source:target:ro"`

5. Creare `internal/ui/output.go`:

   - Funzioni `Success(msg string)`, `Warning(msg string)`, `Error(msg string)`, `Info(msg string)` che stampano con `fmt.Println(style.Render("  " + symbolPrefix + msg))` dove i simboli sono: Success="OK: ", Warning="WARN: ", Error="FAIL: ", Info="" -- coerenti con stile entrypoint.sh Phase 1

|----------|-------------|
| YAML config -> CLI | File YAML locali (progetto e home) parsati da Viper come input non fidato |
| Mount paths -> filesystem | Path dalla config accedono al filesystem host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | internal/mount/resolve.go | mitigate | Usare filepath.Clean() su tutti i path dopo espansione di ~; verificare con os.Stat prima di montare |
| T-02-02 | Information Disclosure | internal/config/config.go | accept | Config YAML contiene solo path locali, nessun segreto. ~/.secrets non montato di default (D-08) |
| T-02-03 | Tampering | YAML config injection | accept | Viper parsing e' sicuro -- nessun eval di codice dal YAML. File sono locali all'utente |
